# セキュリティレビュー

対象のソースコードを読み、脆弱性を洗い出してレビューを行う。

## 対象

- `$ARGUMENTS` が指定されている場合はそのファイル/ディレクトリのみレビューする
- 指定がなければ `src/` 配下の全ソースコードを対象とする

## レビュー観点

以下の観点で脆弱性を探すこと:

### 入力・出力

- ユーザー入力（パラメータ、クエリ、ヘッダー、リクエストボディ）のバリデーション不足
- SQLインジェクション、NoSQLインジェクション
- XSS（クロスサイトスクリプティング）
- コマンドインジェクション、パストラバーサル
- エラーメッセージによる内部情報の漏洩

### 認証・認可

- 認証の欠如・バイパス
- 認可チェックの不足（IDOR等）
- セッション管理の不備
- CSRF対策の欠如

### API設計

- GETリクエストでの状態変更
- レート制限の欠如
- CORS設定の誤り（オリジン、メソッド、ヘッダー）
- 機密データの不適切な露出

### データ管理

- ハードコードされたシークレット（APIキー、トークン、パスワード）
- メモリ上の無制限データ蓄積
- 機密情報のログ出力
- 安全でないデシリアライゼーション

### 依存関係・設定

- 既知の脆弱性を持つ依存パッケージ
- セキュリティヘッダーの欠如
- デバッグ用コードの残存
- 環境設定（開発用設定の本番残存等）

## 出力フォーマット

以下の形式でレポートする:

1. 深刻度順（High → Medium → Low）に並べる
2. 各項目に以下を含める:
   - 深刻度（High / Medium / Low）
   - 該当箇所（ファイルパス:行番号）
   - 問題のコードスニペット
   - 具体的なリスクの説明
   - 修正の提案
3. 最後にまとめの表を出力する

## 注意事項

- 推測ではなく、コードに基づいた具体的な指摘を行うこと
- 一般的なベストプラクティスの列挙ではなく、実際に存在する問題を指摘すること
- 修正提案は具体的なコード例を含めること
